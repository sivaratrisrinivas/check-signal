Release day

A new model ships. You open your benchmark to decide whether to switch. You see one number per model. You can't see which of your own standards that number reflects, or whether a check can tell the models apart at all.

12 of 34 checks give every model the same result.

11always pass, for all 5 models
1always fails, for all 5 models
22actually separate the models
35%of checks can't help you pick

They still count toward every score. That isn't wrong. Some are floors on purpose. But it's worth knowing which checks carry the decision.

4 models missed: R04. Example stays at the definition level

GPT-6.1 Sol, GPT-6 Sol, Opus 5.5, GPT-5.6
Judge's reasoning
GPT-6.1 Sol on R04. Example stays at the definition level: The example stays in the exact task mechanics Dan called "two in the weeds": it walks through asking the AI to critique an opening and then judging that critique ("You save an opening and the request you gave the AI... compare how many of your checks its feedback passes"), sharpening rather than removing the critique-of-a-critique workflow and adding input-saving steps.
GPT-6 Sol on R04. Example stays at the definition level: The example is the workflow the rubric rules out: "Say you ask AI for feedback on an article opening. Give the same opening to several models, then check their feedback," which walks through checking a critique of an opening.
Opus 5.5 on R04. Example stays at the definition level: The example walks through the editing workflow the rubric warns against: "hand a model an opening you've already edited, ask for feedback, and check its answer the way you would."
GPT-5.6 on R04. Example stays at the definition level: The example walks through the critique workflow ("giving feedback on an article opening" goes to several models, then each critique is graded on "Did it catch that the headline buried the strongest claim?"), which is the task mechanics the rubric's FAIL condition names.

Worth a look

Things in the public data that may have a simple explanation. Questions, not bugs. I can't see inside Every's system.

Shared check “ai-wording” fails 4 of 5 models, only in tend-feed-card-writing

  • Evidence on every failing run: “shared AI-tell phrases: its important to note”
  • Passes on all models in the other 4 tasks
  • GPT-6.1 Sol: phrase not found in the public ANSWER.md
  • GPT-6 Sol: no public answer file to compare
  • Sonnet 5.5: phrase not found in the public ANSWER.md
  • GPT-5.6: phrase not found in the public ANSWER.md
  • Opus 5.5 passes; its run is dated 20 Sep 2026 and its evidence says “inspected answer.md”
Is the phrase coming from a file other than the answer, like an input the check also reads?

4 runs show missing or very low token counts

  • Opus 5.5 on article-opening-feedback: 5,915 tokens vs a task median of 52,801
  • Opus 5.5 on personal-benchmark-paragraph-first-draft: 5,446 tokens vs a task median of 120,309
  • Opus 5.5 on tend-feed-card-writing: no token count shown
  • Opus 5.5 on literary-analysis-follow-up: 2,376 tokens vs a task median of 92,408
Are these counts complete? A cost view built on them would favor these runs.

Every cell is one run; runs span 19 Sep to 1 Oct 2026

  • 25 cells, 1 latest run each, so run-to-run variance isn't visible
  • Models with runs on more than one date: Opus 5.5
Would 3 runs per cell change any tie or gap of one check? Every’s own guide suggests running a task three times.

The shared code check read different files on literary-analysis-follow-up

  • GPT-6.1 Sol, GPT-6 Sol, Sonnet 5.5: inspected ANSWER.md, inputs/context.md, inputs/pasted-text.txt
  • Opus 5.5, GPT-5.6: inspected ANSWER.md
Should every model's answer be checked against the same set of files?

The phrase check: I downloaded each failing run's public ANSWER.md and did a plain text match (case and apostrophes ignored).
